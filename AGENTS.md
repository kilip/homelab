# AGENTS.md

Guidance for AI coding agents working in this repository. `CLAUDE.md` is a symlink to this file.

## Project summary

A single-node Kubernetes homelab on an Intel NUC 6CAYH (8 GB RAM). Ansible provisions the node, FluxCD manages everything inside the cluster, and SOPS with age encrypts secrets. All commands run from a Linux workstation through `just`.

## Fixed decisions (do not propose alternatives)

- Distribution: k3s. CNI: bundled Flannel with kube-router network policies (not Cilium).
- Node OS: Ubuntu Server 26, minimized, `ufw` firewall. Single node: control plane and worker together.
- LAN `10.0.0.0/24`, static node IP. Keep the default pod CIDR `10.42.0.0/16` and service CIDR `10.43.0.0/16` unless there is a conflict.
- The Raspberry Pi 3B+ is not part of the cluster (standalone Mosquitto).
- Secrets: SOPS with age everywhere (Ansible and Flux). No Ansible Vault, no plaintext secrets.
- Repository: `github.com/kilip/homelab`. Ansible and Flux live in the same repository.

## Repository layout

```text
justfile, just/        task runner (modules: ansible, sops, flux, k8s)
.sops.yaml             SOPS rules, generated by `just sops init`
ansible/               inventory/, group_vars/, playbooks/, roles/{common,k3s,backup}
k8s/flux-system/       output of `flux bootstrap` plus the root Kustomization
k8s/network/           cert-manager, Traefik config, NetworkPolicies
k8s/storage/           stateful services (postgres, rustfs, redis)
k8s/monitoring/        lightweight monitoring and backups
k8s/apps/<app>/        one folder per application
```

Do not create `infrastructure/` or `clusters/` folders.

## Resource rules

The node has 8 GB of RAM and no HA, so always choose the lightest option.

- Use bundled k3s components first (Traefik, ServiceLB, local-path-provisioner, metrics-server).
- Avoid heavy stacks: full kube-prometheus-stack, service meshes, Longhorn, Cilium, External Secrets Operator.
- Every manifest sets resource `requests` and `limits`.
- State the estimated RAM and CPU for every new component or application.
- Keep the OS minimal: no unneeded packages or snaps, and disable unused services.

## Ansible rules

- Scope: node provisioning only (OS updates, base packages, SSH hardening, kernel/sysctl, ufw, k3s install and configuration, k3s snapshots). Applications, Helm and manifests belong to FluxCD.
- Keep inventory, group_vars and roles separate. Do not put everything in one playbook.
- Inventory groups: `test` (VirtualBox VM) and `prod` (the NUC). `ansible_host` and `ansible_user` are variables and can be overridden with `-e` or `group_vars/all/local.yml` (git-ignored). Derived values (node IP, LAN CIDR for ufw) come from those same variables.
- Tasks must be idempotent. Prefer built-in modules over `shell`/`command`; if unavoidable, set `creates` or `changed_when`. Use fully qualified collection names.
- Pin the k3s version with `k3s_version`.
- Secrets use SOPS (age) through `community.sops`; tasks that handle secrets set `no_log: true`.
- SSH and ufw: SSH is allowed only from the LAN. Install the SSH rule before enabling ufw so a session is never locked out. SSH hardening has two stages controlled by `ssh_disable_password_auth`.
- Mandatory flow for every change: snapshot the VM, then `--limit test --check --diff`, apply to test, verify, and only then `--limit prod` (also `--check --diff` first). The `just ansible` recipes encode this flow; use them instead of calling `ansible-playbook` directly.
- Initial SSH bootstrap (installing openssh-server, copying the public key) is manual and outside Ansible.

## FluxCD rules

- Cluster changes go through Git, not `kubectl apply`, except for bootstrap and debugging.
- Flux bootstraps with path `k8s/flux-system`. The root Kustomization there points to `k8s/network`, `k8s/storage`, `k8s/monitoring` and `k8s/apps`.
- Dependency order (`dependsOn`): network -> storage -> apps and monitoring.
- Resources that need CRDs (for example a cert-manager `ClusterIssuer`) live in a separate Kustomization that `dependsOn` the Kustomization that installs the CRDs.
- Each application is a complete manifest or HelmRelease, ready to commit.

## Secrets

- Secret files are named `*.sops.yaml`. For `k8s/`, only `data` and `stringData` are encrypted.
- The age private key is `age.key` (git-ignored). Never print it into logs, commits or chat. `just sops check` fails when a plaintext secret is present.

## Working agreements

- Write all files and documentation in English.
- Prefer small, reviewable changes. Explain briefly why a step exists, since the repository is also a learning project.
- Check the latest version of a tool before recommending it, and state the version used.
- Mark destructive steps and ask for confirmation before running them (for example deleting data, `apply-prod`, or restoring snapshots).
- Verify your work: run `just ansible syntax` and `just ansible lint` for Ansible changes, and `just sops check` before committing.
- Commits are signed. Do not commit secrets, kubeconfigs or the age key.
