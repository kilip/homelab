# homelab

A single-node Kubernetes homelab running on an Intel NUC. The node is provisioned with Ansible, the cluster is managed GitOps-style with FluxCD, and secrets are encrypted with SOPS and age.

> **Status:** repository scaffold and Phase 1 (OS preparation) files are in place. See the [roadmap](#roadmap).

## Stack

| Area | Choice |
|---|---|
| Hardware | Intel NUC 6CAYH, 8 GB RAM |
| Topology | Single node (control plane and worker on the same machine) |
| OS | Ubuntu Server 26, minimized install, no desktop; `ufw` firewall |
| Kubernetes | k3s with bundled Flannel and kube-router network policies, Traefik, ServiceLB and local-path-provisioner |
| Network | LAN `10.0.0.0/24`, static node IP, default k3s pod CIDR `10.42.0.0/16` and service CIDR `10.43.0.0/16` |
| Provisioning | Ansible (node only: OS, SSH, firewall, kernel, k3s install, k3s backup) |
| GitOps | FluxCD (everything that runs inside the cluster) |
| Secrets | SOPS with age |
| Task runner | [just](https://github.com/casey/just) |
| Test environment | VirtualBox VM on the workstation, same specs as the NUC, bridged network |

A Raspberry Pi 3B+ is **not** part of the cluster; it runs Mosquitto standalone.

This is a single node, so there is no high availability. Backups (k3s snapshots and application data) are mandatory.


## Prerequisites

Install these on the workstation that runs Ansible and Flux (a Linux machine). `just doctor` checks them.

| Tool | Notes |
|---|---|
| [just](https://github.com/casey/just) | Developed with 1.59.0 |
| ansible-core | Developed with 2.21.5 (part of Ansible 14.5.0); needs Python 3.12 to 3.14 on the control node |
| [age](https://github.com/FiloSottile/age) and [sops](https://github.com/getsops/sops) | Latest stable releases |
| kubectl, [flux](https://fluxcd.io/flux/installation/) | Needed from the Flux phase onwards |
| ansible-lint (optional), VirtualBox `VBoxManage` (optional) | Linting and test VM snapshots |

The Ansible collections are pinned in `ansible/requirements.yml` (`ansible.posix` 2.2.x, `community.general` 13.5.x, `community.sops` 2.5.x, matching Ansible 14.5.0).

## Quick start (Phase 1: OS preparation)

### 1. Install the collections

```bash
just doctor
just ansible deps
```

### 2. Bootstrap SSH (manual, once per machine, for the VM and the NUC)

Ansible needs SSH access first, and this step is intentionally done by hand.

```bash
# On the machine console, with its static IP already configured:
sudo apt-get update && sudo apt-get install -y openssh-server

# From the workstation:
ssh-copy-id -i ~/.ssh/id_ed25519.pub <user>@<node-ip>
ssh <user>@<node-ip>    # must log in with the key, without a password prompt
```

### 3. Set machine-specific values

The addresses and users in `ansible/group_vars/all/main.yml` are placeholders. Override them in a git-ignored file:

```bash
cp ansible/group_vars/all/local.yml.example ansible/group_vars/all/local.yml
$EDITOR ansible/group_vars/all/local.yml
just ansible ping test
```

Alternatively pass them on the command line: `just ansible check-test -e test_host_ip=10.0.0.50 -e test_ssh_user=anthonius`.

### 4. Follow the mandatory change flow

Every change goes through the test VM first.

```bash
just ansible snapshot       # 1. snapshot the test VM
just ansible check-test     # 2. dry run (--check --diff)
just ansible apply-test     # 3. apply to the VM, then verify it
just ansible check-prod     # 4. dry run on the NUC
just ansible apply-prod     # 5. apply to the NUC (asks for confirmation)
```

The firewall allows SSH only from `lan_cidr` (default `10.0.0.0/24`). Run Ansible from a machine inside that network, and note that the SSH allow rule is installed before `ufw` is enabled so a running session is never cut off.

### 5. Verify (expected results on the node)

| Check | Command | Expected |
|---|---|---|
| Firewall | `sudo ufw status verbose` | `Status: active`, default deny incoming, `22/tcp ALLOW IN 10.0.0.0/24` |
| Time zone | `timedatectl show -p Timezone` | `Timezone=UTC` |
| Swap | `swapon --show` | no output |
| Kernel modules | `lsmod \| grep -E 'overlay\|br_netfilter'` | both modules listed |
| Forwarding | `sysctl net.ipv4.ip_forward` | `net.ipv4.ip_forward = 1` |
| SSH | `sudo sshd -T \| grep -E 'permitrootlogin\|passwordauthentication'` | `permitrootlogin no`; `passwordauthentication yes` until stage 2 |
| Services | `systemctl is-enabled snapd.service` | `disabled` (or the unit does not exist) |

### 6. SSH hardening, stage 2

Password login is disabled in two stages so you cannot lock yourself out.

1. Keep the default `ssh_disable_password_auth: false` and apply.
2. Open a **new** terminal and confirm that key-based login works.
3. Set `ssh_disable_password_auth: true` in `local.yml` and run the change flow again. The role refuses to proceed if the SSH user has no `authorized_keys`.

## Command reference

Run `just` to list everything.

| Command | Purpose |
|---|---|
| `just doctor` | Check that the required tools are installed |
| `just ansible deps` / `deps-upgrade` | Install or upgrade the pinned collections |
| `just ansible syntax` / `lint` | Validate or lint playbooks and roles |
| `just ansible ping [test\|prod]` | Check SSH connectivity |
| `just ansible snapshot` / `snapshots` | Take or list VirtualBox snapshots of the test VM |
| `just ansible check-test` / `apply-test` | Dry run or apply on the test VM |
| `just ansible check-prod` / `apply-prod` | Dry run or apply on the NUC |
| `just sops init` | Generate the age key and `.sops.yaml` |
| `just sops pubkey` / `export-key` | Print the public key, or the private key for backup |
| `just sops encrypt` / `decrypt` / `edit <file>` | Work with encrypted files |
| `just sops check` | Fail if a secret is committed in plaintext |
| `just flux check` / `bootstrap` / `reconcile` / `status` / `logs` | FluxCD helpers (Flux phase) |
| `just k8s check` / `nodes` / `pods` / `top` / `events` / `build` | Cluster inspection helpers |

Extra `ansible-playbook` flags can be appended to the check and apply recipes, for example `just ansible check-test --tags ssh`.

## Secrets

Secrets are encrypted with SOPS and age. Never commit plaintext secrets or the private key.

```bash
just sops init          # creates age.key (git-ignored) and .sops.yaml; never overwrites
just sops export-key    # copy the private key into a password manager NOW
```

Secret files are named `*.sops.yaml`. Ansible reads them through the `community.sops` collection and Flux decrypts them in-cluster using a `sops-age` secret (`just flux sops-secret`). Losing the private key means losing every encrypted secret, so back it up.

## Conventions

- All files and documentation are in English.
- Everything inside the cluster changes through Git (FluxCD), not manual `kubectl apply`, except for bootstrap and debugging.
- Prefer the components bundled with k3s and keep the footprint small: the node has 8 GB of RAM.
- Commits are signed.
